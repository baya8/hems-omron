# バッチについて

本ドキュメントは、バッチに関する仕様を記載している。

## 要件

機器の詳細は README_OMRON.mdを参照。
omron製の送信ユニットから、1日1回各種パラメータをAPI経由で取得し、DBへ保存するバッチを作成する。

## アーキテクチャ

### 言語・フレームワーク

golangでバッチを作りたい。
おすすめのフレームワークがあれば教えてほしい。
後述する処理ロジックにある通り、dockerコンテナとして起動することを想定。

### DB

MariaDB、といったRDBでかつOSS寄りの志向を持ったデータベースがいい。
MariaDB以外におすすめがあれば教えてほしい。
後述する処理ロジックにある通り、コンテナとして起動することを想定。
バッチとは別のコンテナとして起動しておき、常時起動させておく。

## 処理ロジック

バッチの起動は、Synology NAS のdocker上を想定している。
AM 1:00に起動し、前日の発電量や消費電力量、買電量、売電量といった時間ごとの各パラメータを取得する。



## TBL構成

### データTBL

太陽光発電の送信ユニットからAPI経由で取得した生データを保存する。
TBLの主キーは日付、時間をキーして、取得できた全パラメータを絡むとして格納。
それ以外は、取得日時、補正日時のカラムを入れたい。

- カラム
  - 発電量1
    - パワーコントローラ1から受信した発電量
  - 発電量2
    - パワーコントローラ2から受信した発電量
  - 発電量3
    - パワーコントローラ3から受信した発電量
    - 今回の設備は2つまでしかないので、3~5は使わない（null）の想定
  - 発電量4
  - 発電量5
  - 発電量合計
    - 1~5の発電量合計値
  - 消費電力量
  - 売電量
  - 買電量
  - 取得日時
    - APIから取得し、DBへ保存した日時
    - APIから取得に失敗した場合も値が入る
  - 再取得日時
    - 1回目のAPIから取得に失敗した場合、2回目以降リトライして取得ができた場合に入る値。
    - 何回失敗しても、成功するまで値は入らない。
  - 補正日時
    - 手で補正した場合に値が入る
    - デフォルトnull

### データ取得失敗TBL

データTBLに登録するデータをAPI経由で取得しDBへ保存する際、何かしらの理由で取得ができなかった場合にデータが登録される。
キーは、日付、時刻、取得成否(isFailed)というカラムにする。

これでデータTBL内で取得に失敗したデータをこちらに格納し、バッチでリトライするパラメータのもととしたい。かつ取得に成功したレコードはisFailedをtrueで保存することで、成否の判断もできる。
